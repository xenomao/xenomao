# Claude 4.8 運用ガイド — Effort 選択 & ダイナミックワークフロー

- 対象プラン: **Pro**
- 作成日: 2026-05-30
- 対象: DigiLab Beauty プロジェクト（約70ファイル規模）に最適化した運用方針

---

## 1. Effort（努力度）の選び方

> ⚠️ **Pro の既定モデルは Sonnet 4.6**（Opus 4.8 ではない）。Sonnet 4.6 の Effort は
> `low/medium/high/max` で **`xhigh` 非対応**（指定すると `high` に縮退）。`xhigh` や
> ダイナミックワークフローの本領を使うときは `/model opus` で **Opus 4.8** に切替える。
> Opus は Pro では消費が速く、上限超過時は自動的に Sonnet へフォールバックすることがある。

Claude Code では `/effort` でタスクごとに努力度を選べます。本プロジェクトは
**固定せず都度選択**する方針です。

| レベル | 永続性 | 対応モデル | 使いどころ（本プロジェクト） |
|---|---|---|---|
| `low` / `medium` | セッション跨ぎで保持 | 全モデル | 誤字修正、リンク差し替え、体裁調整、低コスト作業 |
| `high` | 同上（既定） | 全モデル | ブログ執筆・編集、スクリプト小修正 ← **通常はこれ** |
| `xhigh` | 同上 | **Opus 4.7/4.8 のみ** | 複数記事の一括編集、DB/スクリプトのリファクタ、監査 |
| `max` | **そのセッションのみ** | 全モデル | 最難関の単発のみ（※過剰思考に陥りやすく逓減あり） |
| `ultracode` | セッションのみ | Claude Code 設定 | `xhigh` 送信＋ダイナミック WF 自動化（※本 PJ では常用しない） |

操作:
- `/effort` … 引数なしでスライダー、`/effort high` で直接指定、`/effort auto` で既定に戻す
- `/model opus` … モデルを Opus 4.8 に切替（`/model` のスライダーでも Effort 調整可）
- `/fast` … 高速モード切替（4.8 で約3倍安価）。軽作業の体感速度向上に
- `ultrathink` … プロンプトに入れるとその回だけ深掘り（Effort 設定は変えない）。都度方針に最適
- 既定を固定したくなった場合のみ `settings.json` に `"effortLevel": "high"` を設定
  （`max`/`ultracode` は不可。env 変数 `CLAUDE_CODE_EFFORT_LEVEL` が全てに優先）。今回は未設定

**推奨運用（Pro）: 通常は Sonnet 4.6＋`high`。重いバッチ作業の直前だけ `/model opus` ＋ `xhigh`。**

## 2. ダイナミックワークフロー（Pro）

### 2-1. 有効化（初回のみ・あなたの操作）
1. Claude Code で `/config` を開く
2. 「Dynamic workflows」セクションを有効化（**Pro は手動有効化が必要**）
3. 以降、プロンプトで「ワークフローを作って」等と依頼すると起動候補になる

> Max / Team は既定で ON、Enterprise は管理者が有効化。**Pro のみ手動。**

### 2-2. 仕組み（要点）
- Claude がプロンプトに応じてオーケストレーションスクリプトを動的生成
- タスクを分割し、**最大16同時／合計最大1,000**のサブエージェントに並列割当
- 自己検証（あるエージェントが解決し、別エージェントが反証。収束まで反復）
- 進捗は自動保存。**中断しても再開可**
- **実行前にプレビュー＋確認**（消費が通常セッションより大幅増のため）

### 2-3. 使う／使わない の判断（本 PJ 向け）
このプロジェクトは約70ファイル。原則は **通常セッションで処理し、下記のような
"数十項目を横断する一括作業" のときだけ明示的に WF を呼ぶ**。

WF が向く例（このPJの現実的バッチ）:
- 全ブログ記事（約50本）のテンプレ統一／SEO 最適化／CTA 差し込み一括リライト
- 19社分のティア別（A/B/C）営業アウトリーチ文面の一括生成
- `blog/japan` ↔ `blog/global` の多言語ローカライズ一括展開
- 全記事のデッドリンク・事実確認・古い数値の横断監査

WF が不要な例:
- 1〜数本の記事編集、単発のスクリプト修正、DB 1テーブルの調整
  → 通常セッション＋ `high` / `xhigh` で十分

### 2-4. 起動の仕方
- 明示依頼する（例は §3 のレシピ参照）
- 起動前に必ず**スコープ**を伝える: 対象ディレクトリ／完了条件／除外対象
- プレビューが出たら**消費見込みを確認してから承認**

### 2-5. コスト注意（Pro）
- WF は通常セッションの数倍〜の消費。Pro の利用上限に当たりやすい
- まず小さい範囲（例: 5記事）で試運転し、問題なければ全体へ拡大
- 中断・再開が効くので、上限が心配なら区切って実行

## 3. コピペ用レシピ（必要時のみ使用）

各ブロックをそのまま Claude Code に貼り付けて使う。すべて「まず少数で試運転 → 承認後に全体」を前提。

### A. 全ブログ記事のテンプレ統一リライト

    blog/ 配下の全 .md 記事を対象に、CTA を blog/cta_template.md 準拠へ統一し、
    H2/H3 の見出し構成とブランドカラー表記（紫#8b2fc9 / ピンク#d946a8 / ゴールド#ffd700）
    を揃えるワークフローを作って。各記事は元の主旨を保持すること。
    まず blog/japan の5本で試運転し、承認後に全体へ拡大して。

### B. 19社分のティア別 営業アウトリーチ一括生成

    db/esthetic_industry_dd_19companies.csv の19社を対象に、Tier(A/B/C)別のトーンで
    営業アウトリーチ文面を1社1ファイルで生成するワークフローを作って。
    出力は docs/templates 配下、ファイル名は snake_case、日本語。
    まず Tier A の3社で試し、承認後に残りへ展開して。

### C. 多言語ローカライズ一括展開

    blog/japan の記事を blog/global 向けに英語ローカライズするワークフローを作って。
    直訳でなく、海外エステ業界の読者向けに見出し・CTA・事例を最適化。
    原文の事実は保持。まず3本で試運転し、承認後に全体へ。

### D. 全記事の横断監査（デッドリンク・事実確認）

    blog/ 配下の全記事を横断監査するワークフローを作って。
    チェック項目: 切れリンク、古い統計値・年号、ブランドカラー表記ゆれ、CTA 欠落。
    結果を docs/reports に1本のレポートとしてまとめ、修正は提案のみ（自動修正しない）。
