# セキュリティ対応メモ — 秘匿情報のGitコミット

- 作成日: 2026-05-30
- 最終更新: 2026-06-06（公開コミットの実値を検証し、実態に合わせて訂正）
- 重大度: **中**（当初「高」と評価したが、実際に公開されていた実キーは NewsAPI 1個のみと判明）

---

## 1. 何が起きていたか

`.gitignore` が UTF-16（BOM付き）で保存されており、Gitが解釈できず **`.env` が除外されていなかった**。
結果、`.env` と `scripts/main.py` がリポジトリにコミットされていた。

### ⚠️ 重要：実際に「公開」されていた値の検証結果（2026-06-06）

`xenomao/xenomao` は **public（公開）リポジトリ**（誰でも閲覧可）。
ただし、公開コミット（main / 82d6ee6）の `.env` の**実際の中身**を確認したところ、
実値が入っていたのは **NewsAPIキーのみ**だった:

| 対象 | 公開コミットでの値 | 実際の漏洩 |
|---|---|---|
| `NEWSAPI_KEY` | `d28b...068`（実値あり） | 🟢 漏洩（ただし無料・課金なし・実害小） |
| `EMAIL_PASSWORD` | **空欄**（`EMAIL_PASSWORD=`） | ✅ 漏れていない |
| `SERPAPI_KEY` | **空欄**（`SERPAPI_KEY=`） | ✅ 漏れていない |
| `scripts/main.py` | NEWSAPI_KEY を直書き | 🟢 漏洩（NewsAPIと同じキー） |

→ コミットされた `.env` は初期テンプレート版で、メール/SerpAPIは「将来使用」として空欄のまま。
   メールパスワード等の実値は**手元の（コミットされていない）`.env`** にのみ存在し、公開されていない。

---

## 2. 今回コードで対応済み（このブランチ）

- ✅ `.gitignore` を UTF-8 に修正し、`.env` / `__pycache__` / 生成診断レポートを除外
- ✅ `git rm --cached .env` で `.env` の追跡を解除（ローカルのファイルは保持）
- ✅ `scripts/main.py` のハードコードを `os.getenv("NEWSAPI_KEY")` に変更（`.env`参照）
- ✅ `.env.example` を追加（値は空のプレースホルダ。何を設定すべきか明示）

> ⚠️ 注意: これらは「**今後の追跡を止める**」対応。**過去のコミット履歴には秘密情報が残ったまま**。

---

## 3. 対応方針と判断（2026-06-06 確定）

### 3-0. 結論：NewsAPIキーは「現状維持（再発行しない）」で確定
ユーザー判断により、公開済みNewsAPIキーは**再発行せず現状維持**とする。理由:
- NewsAPIは**無料プラン＝課金が発生しない**。不正利用されても金銭被害なし
- 起こりうる最悪ケースは「無料レート枠を他人に消費され、ニュース収集が一時的に失敗」する程度
- 無料プランは**ユーザー自身でのキー再生成機能がない**（再発行の手段が乏しい）
- メール／SerpAPIの実値は**そもそも公開されていない**ため対応不要

### 3-1. ただし以下の場合は「即・再発行」に方針転換すること（重要）
NewsAPIを**有料プランにアップグレードした場合**、同じキーが課金対象になる。
その時は、アップグレード前に必ず新キーへ差し替えること（別メールで新規登録など）。

### 3-2. 危険の早期サイン（次回セッションで Claude がチェック可能）
「不正利用されていないか」は、以下の兆候で間接的に検知できる:

- [ ] **NewsAPIの使用量が不自然に増えている** → 他人がキーを使っているサイン
      （https://newsapi.org/account のリクエスト数を確認。自分の利用より明らかに多ければ要注意）
- [ ] **ニュース収集スクリプトが急に429（レート超過）で失敗し始めた** → 枠を食われている可能性
- [ ] NewsAPIを有料化した／する予定がある → 3-1 を発動

> 📌 Claude へ: 次回セッションでこのプロジェクトに触れる際、上記サインに該当しそうな
> 兆候（スクリプトの429エラー、使用量の異常）に気づいたら、ユーザーに能動的に知らせること。
> ただし常時監視はできない（Claudeはセッション内でのみ稼働）点は正直に伝える。

### 3-3. （任意・非推奨）Git履歴からの完全削除
- 秘密を含むコミット(82d6ee6)は **main を含む全ブランチ**に存在。完全削除には全履歴の
  書き換え＋強制プッシュが必要で、**極めて破壊的**（既存クローン・PRが壊れる）。
- NewsAPIキーは実害が小さいため、**履歴削除は割に合わない**。実施しない。

## 4. 再発防止

- 秘密情報は常に `.env`（gitignore済み）に置き、コードへ直書きしない
- 新しいキーを足すときは `.env.example` にプレースホルダだけ追記
- コミット前に `git status` で `.env` や鍵が含まれないか確認
- **この リポジトリは public**。今後、実値を含むファイルを絶対にコミットしないよう特に注意
