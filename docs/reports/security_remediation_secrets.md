# セキュリティ対応メモ — 秘匿情報のGitコミット

- 作成日: 2026-05-30
- 重大度: **高**（APIキー・メールパスワードがGitリポジトリに平文で混入）

---

## 1. 何が起きていたか

`.gitignore` が UTF-16（BOM付き）で保存されており、Gitが解釈できず **`.env` が除外されていなかった**。
結果、以下がリポジトリにコミットされていた:

| 対象 | 内容 | 状態 |
|---|---|---|
| `.env` | NEWSAPI_KEY / SMTP_SERVER / EMAIL_FROM / EMAIL_PASSWORD / SERPAPI_KEY | 初回コミット(82d6ee6)から追跡 |
| `scripts/main.py` 35行 | NEWSAPI_KEY をソースに直書き | 同上 |

`xenomao/xenomao` リポジトリを閲覧できる範囲に、これらの秘密情報が露出していた。

---

## 2. 今回コードで対応済み（このブランチ）

- ✅ `.gitignore` を UTF-8 に修正し、`.env` / `__pycache__` / 生成診断レポートを除外
- ✅ `git rm --cached .env` で `.env` の追跡を解除（ローカルのファイルは保持）
- ✅ `scripts/main.py` のハードコードを `os.getenv("NEWSAPI_KEY")` に変更（`.env`参照）
- ✅ `.env.example` を追加（値は空のプレースホルダ。何を設定すべきか明示）

> ⚠️ 注意: これらは「**今後の追跡を止める**」対応。**過去のコミット履歴には秘密情報が残ったまま**。

---

## 3. あなたが実行すべき対応（最優先・コード側では不可）

### 3-1. 漏れたキー類を「無効化＆再発行」する（最重要）
履歴に残る以上、**鍵そのものを使えなくする**のが最も確実。

- [ ] **NewsAPI**: ダッシュボードでキーを再発行（旧キー `d28b...` は失効させる）
- [ ] **メール (EMAIL_PASSWORD)**: アプリパスワードを破棄し再発行。通常パスワードなら変更
- [ ] **SerpAPI**: キーを再発行
- [ ] 再発行した値は、新しい `.env`（コミットされない）にのみ記載

### 3-2. （任意）Git履歴från秘密を完全削除する
鍵を再発行すれば履歴に残っても無害化されるが、それでも消したい場合:

- `git filter-repo`（推奨）または BFG Repo-Cleaner で `.env` を全履歴から除去
- **履歴を書き換えるため、強制プッシュと全クローンの作り直しが必要**。影響が大きいので、
  共同作業者がいる場合は事前共有のうえ実施すること。
- この操作は破壊的なので、実施前に必ずバックアップ（リポジトリの複製）を取る。

---

## 4. 再発防止

- 秘密情報は常に `.env`（gitignore済み）に置き、コードへ直書きしない
- 新しいキーを足すときは `.env.example` にプレースホルダだけ追記
- コミット前に `git status` で `.env` や鍵が含まれないか確認
